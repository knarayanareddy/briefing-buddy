## Findings ledger

- **BB-01 — High; confirmed static.** [`github-oauth-callback/index.ts:75-85,87-125`](https://github.com/knarayanareddy/briefing-buddy/blob/46ab418dc9efa26a61c1bea921994ec474f44662/supabase/functions/github-oauth-callback/index.ts#L75-L125) awaits secret, config, connection and health writes without inspecting their returned `error`, then returns `{ ok: true }`. A rejected write can leave a missing token or inconsistent connector state while reporting success; state cleanup errors are also ignored. Check each result, use an atomic or recoverable persistence design, and return success only after durable verified state. Network-throw behavior and actual database constraints remain untested.

## Five-discipline assessment

Additional short source anchors for the ledger: BB-01 returns `{ ok: true }` after unchecked result-bearing writes; BB-02 records `conclusion: failure` in the historical run, not a reviewer-executed test; BB-04 renders `<label className=` and `<Input` without paired `htmlFor`/`id` in the cited range. The source quotations in BB-03/05/06 identify their specific controls and versions.

**Correctness:** BB-01 is a concrete failure-to-observe database results; callback state is compared per user before token exchange ([callback:34-44](https://github.com/knarayanareddy/briefing-buddy/blob/46ab418dc9efa26a61c1bea921994ec474f44662/supabase/functions/github-oauth-callback/index.ts#L34-L44)). Expiry, replay resistance and other providers' implementations were not checked.

**Automation/testing:** BB-02 blocks confidence. The workflow explicitly excludes service-role milestone integration tests ([CI:58-63](https://github.com/knarayanareddy/briefing-buddy/blob/46ab418dc9efa26a61c1bea921994ec474f44662/.github/workflows/ci.yml#L58-L63)); existence of test files is not evidence they pass or cover OAuth persistence. BB-06 affects reproducibility.

**DevOps/operations:** Scheduling needs manual setup according to [`README.md:72-73`](https://github.com/knarayanareddy/briefing-buddy/blob/46ab418dc9efa26a61c1bea921994ec474f44662/README.md#L72-L73). Cron delivery, failure alerts, rollback and restores are unobserved. BB-05 complicates environment recovery.

**OWASP/security:** [`auth.ts:33-45,53-73`](https://github.com/knarayanareddy/briefing-buddy/blob/46ab418dc9efa26a61c1bea921994ec474f44662/supabase/functions/_shared/auth.ts#L33-L73) validates JWTs through Supabase or accepts a configured internal key with optional caller-selected user ID. This is a privileged boundary, not proof of a bypass. RLS, per-endpoint authorization, internal-key distribution, share-token access, SSRF and prompt injection protections remain unverified; the tree contains relevant files but their presence proves nothing. The callback encrypts the token before storage ([callback:75-85](https://github.com/knarayanareddy/briefing-buddy/blob/46ab418dc9efa26a61c1bea921994ec474f44662/supabase/functions/github-oauth-callback/index.ts#L75-L85)); key rotation, redaction, retention and downstream handling were not verified. BB-03 and BB-06 require production controls.

**UI/UX/accessibility:** BB-04 affects identifying the login field and header controls. [`Index.tsx:26-35,41-46`](https://github.com/knarayanareddy/briefing-buddy/blob/46ab418dc9efa26a61c1bea921994ec474f44662/src/pages/Index.tsx#L26-L46) hides reveal content until an intersection observer adds a class; assess no-JS/observer failure and reduced-motion behavior rather than asserting a measured failure. No browser, screen-reader, responsive or contrast testing was performed.
